The memory map

32-bit address space

Every memory and every peripheral register has a fixed address, set in silicon by ST. This is the whole chip at a glance.

0x0000 0000ITCM 64 KBfastest code
0x0800 0000Flash 1 MByour program
0x2000 0000DTCM 128 KBfastest data
0x2400 0000AXI SRAM 320 KBmain RAM (CubeIDE default)
0x3000 0000SRAM1 + SRAM2 32 KBDMA buffers
0x3800 0000SRAM4 16 KBlow-power domain, BDMA
0x3880 0000Backup SRAM 4 KBsurvives Standby / VBAT
0x4000 0000PeripheralsGPIO, UART, CAN registers
0x9000 0000Octo-SPIexternal flash / HyperRAM (XiP)

Addresses up to 0x3880 0000 from RM0468 pp.133–140. 0x9000 0000 is the usual STM32H7 Octo-SPI window; confirm in RM0468 when you reach that chapter.

01

Flash with ECC

1 MB · non-volatile
  • Flash keeps its contents with the power off. Your program lives here, starting at 0x0800 0000.
  • It's split into 8 sectors of 128 KB. Erasing works one whole sector at a time, which shapes how a bootloader is laid out (Weeks 25–29).
  • ECC (error-correcting code) stores check bits with every flash word. A single flipped bit is corrected automatically. Two flipped bits are detected and raise a fault. This is essential for automotive and safety work.
02

564 KB of SRAM, in pieces

volatile · all with ECC

SRAM is the fast working memory for variables, stack and buffers. It loses its contents at power-off. The 564 KB is not one block:

RegionSizeAddressUse it for
DTCM128 KB0x2000 0000Fastest data: stack, critical variables
ITCM64 KB (up to 256 KB)0x0000 0000Fastest code: interrupt handlers, control loops
AXI SRAM128 KB + 192 KB shared0x2400 0000Main RAM, big buffers, LCD frame buffers
SRAM1 / SRAM216 KB + 16 KB0x3000 0000DMA buffers
SRAM416 KB0x3800 0000Low-power domain, BDMA buffers
Backup SRAM4 KB0x3880 0000Data that must survive Standby
128 + 64 + 128 + 192 + 16 + 16 + 16 + 4=564 KB
03

TCM: tightly coupled memory

ITCM + DTCM

TCM is wired directly to the core, bypassing the bus system.

  • Always 0 wait states at the full 550 MHz.
  • Deterministic: every access takes exactly the same time. Cached memory is fast on a hit and slow on a miss.
  • It doesn't need the cache, because it's already as fast as the cache.

The 192 KB shared block can be split between ITCM and AXI SRAM in 64 KB steps, set by an option byte. That's the "up to 256 KB can remap on ITCM" in the datasheet.

Pitfall: DMA and DTCM

DMA1 and DMA2 can't access DTCM, ITCM, SRAM4 or backup RAM (RM0468 p111). If you move a DMA buffer into DTCM, the transfer silently fails. Keep DMA buffers in AXI SRAM or SRAM1/2.

04

Backup SRAM

4 KB · survives Standby

These 4 KB keep their contents in Standby mode, and through power-off if a coin cell is connected to VBAT. Enable the backup regulator first (HAL_PWREx_EnableBkUpReg()). Typical uses are a trip counter, the last fault code, or a bootloader flag.

External memory interfaces

FMC · Octo-SPI · SDMMC

FMCParallel external SRAM, SDRAM, NOR, NAND (up to 24-bit bus)Not used

  • XiP (execute in place): the external flash appears in the address map, so the CPU runs code and reads assets from it directly, with the L1 cache hiding the slowness. TouchGFX keeps images and fonts there.
  • On-the-fly decryption (OTFDEC): code stored encrypted in external flash is decrypted as it's read. Dumping the flash chip gives only scrambled data.
  • Memory chips are sold in bits. Divide by 8 for bytes.
06

Bootloader and security services

SFI · SB-SFU
  • System bootloader: a small program in ST's ROM, separate from your code. Hold BOOT0 high at reset and it can flash firmware over UART or USB, even when your own firmware is broken.
  • SFI (secure firmware install): firmware is sent to the chip encrypted at the factory, so the manufacturer can't read your code.
  • SB-SFU (secure boot and secure firmware update): ST's reference design for checking firmware signatures at boot and updating safely. Closely related to your UDS bootloader in Weeks 25–29.

Cache hit and miss

how slow memory looks fast

Think of the cache as your desk and main memory as the library shelves. The CPU checks the desk first.

Hit

already in the cache → used at once
0 wait states

Miss

fetched from memory → copied into the cache
several wait states

A miss fetches a whole 32-byte cache line, not just the byte asked for. Programs tend to use nearby data next (locality), so one slow trip pays for several fast hits.

// data[0] misses and loads data[0..7] (32 bytes)
// data[1..7] hit; data[8] misses; about 7 of every 8 reads hit
for (int i = 0; i < 1000; i++)
    sum += data[i];

The hardware manages hits and misses. Your jobs are to enable the caches (SCB_EnableICache(), SCB_EnableDCache()) and to handle DMA buffers correctly.

Pitfall: DMA and the D-cache

DMA writes straight to RAM. The CPU may then read an old copy from its D-cache. CubeIDE puts variables in AXI SRAM, which is cached, so this is the default trap for DMA buffers.

Fixes (Week 9)

Call SCB_InvalidateDCache_by_Addr() before reading a DMA receive buffer, or use the MPU to mark the buffer's region as non-cacheable.

Who decides where things go

silicon · compiler · linker · you
1

Silicon (ST)

Region addresses and sizes are fixed in the chip. Only the ITCM/AXI split can be changed, by option byte.

2

Compiler

Sorts each item into a named section by type. It knows nothing about addresses.

3

Linker script (.ld)

Lists the regions and says which section goes into which one. CubeIDE generates it once per project; after that it's yours to edit.

4

You

Override single items with a section attribute plus a matching rule in the linker script.

/* 1. in C: tag the buffer */
__attribute__((section(".dma_buffer")))
uint8_t uart_rx_buf[256];

/* 2. in the .ld file: say where the section goes */
.dma_buffer (NOLOAD) : { *(.dma_buffer) } >RAM_D2

The .map file in your build folder lists the final address of every function and variable.

  • .bss costs no flash; .data costs flash and RAM. Use const to keep tables in flash.
  • Keep big buffers out of functions. A 4 KB local array takes 4 KB of stack on every call, and stack overflows show up as hard faults.
  • Avoid malloc() in firmware. The heap fragments over time, and most automotive coding standards ban it.

Check yourself

tap to reveal
UART DMA receive fails, but the same code works without DMA. What's the likely memory cause?

Most likely the D-cache: the buffer is in cached AXI SRAM and the CPU reads a stale copy. Invalidate the cache lines before reading, or make the region non-cacheable with the MPU. If the buffer was moved to DTCM, DMA1/DMA2 can't reach it at all.

Why put a motor-control interrupt handler in ITCM instead of flash?

ITCM is always 0 wait states and deterministic. Code in flash depends on the I-cache, and a miss adds flash wait states at unpredictable moments.

How many megabytes is the 512-Mbit Octo-SPI flash?

512 Mbit ÷ 8 = 64 MB.

Where would you store a "last fault code" so it survives Standby?

In the 4 KB backup SRAM at 0x3880 0000, after enabling the backup regulator. The RTC backup registers also work for a few words.

Which section does uint32_t count = 0; go in, and does it use flash?

.bss. Zero-initialized data takes no flash; the startup code clears it.
