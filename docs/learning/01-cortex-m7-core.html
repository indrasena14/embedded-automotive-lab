01

What a core is

CPU

The core is the CPU: the part of the chip that runs your instructions. It fetches an instruction, decodes it, executes it, and repeats. Everything else on the chip (memories, GPIO, UART, CAN, timers) is built around it and talks to it over internal buses.

Who made what

Arm® Cortex®-M7
  • Arm designs CPU cores but doesn't make chips. It licenses its designs.
  • ST licenses the Cortex-M7, adds memories and peripherals, and manufactures the result as the STM32H735. NXP, Microchip and others license the same core, so core knowledge carries over between vendors.

03

32-bit

register width
  • Registers are 32 bits wide, so the CPU handles a 32-bit number in one instruction.
  • Addresses are 32 bits too: a 4 GB address space (232 bytes).
  • Flash, RAM and every peripheral register live at an address. Writing a value to a GPIOC register is what turns LD1 on. This memory map is the subject of Week 2's register-level blink.
04

DP-FPU

double-precision floating point

A floating-point unit is hardware for decimal math. Without one, 3.14f * 2.5f runs as a software routine of dozens of instructions. With one, it's about one instruction.

Double precision means both float (32-bit) and double (64-bit) run in hardware. Many smaller cores, such as the M4, accelerate only float. It matters for GPS math, filters and motor control.

05

L1 cache and 0-wait states

32 KB I + 32 KB D

The core runs at 550 MHz, but flash is much slower. Without help the CPU stalls for several cycles on every read; each stalled cycle is a wait state. A cache is a small, very fast memory inside the core that keeps copies of recently used instructions (I-cache) and data (D-cache). L1 means level 1, the cache closest to the CPU.

Cache hit

CPU → L1 cache ✓
0 wait states

Cache miss

CPU → L1 cache ✗ → flash / RAM / OctoSPI → copy into cache
several wait states

"0-wait state execution" in the datasheet means cache hits. It also applies to the external OctoSPI flash and HyperRAM on your board, which are slower still.

Week 10 pitfall: cache coherency

The DMA copies data straight into RAM without the CPU. If the CPU then reads that address, it can get a stale copy from its D-cache. This is one of the most common STM32H7 bugs. The MPU (section 07) is the usual fix.

06

Up to 550 MHz

clock frequency
1 cycle=1 / 550 000 000 s≈1.8 ns
  • 550 MHz is a maximum. You set the real speed in the clock tree (Week 3).
  • After reset the chip runs on its internal 64 MHz oscillator (HSI).
  • A faster clock uses more power, so products often run below the maximum.
07

MPU

memory protection unit

The MPU lets you set rules for regions of memory: read-only, never execute code from here, don't cache this region. It catches bugs such as a stack overflowing into other data, and with an RTOS it keeps tasks from damaging each other's memory. On the H7 it also controls cacheability, which is the standard fix for the DMA problem in section 05.

Linux needs an MMU. That's the main reason your H735 can't run Linux and your MP257 can.

08

DMIPS

Dhrystone 2.1 benchmark

Dhrystone is an old, standard benchmark for comparing CPUs. DMIPS means Dhrystone millions of instructions per second. DMIPS/MHz measures how much work the core does per clock cycle.

2.14 DMIPS/MHz×550 MHz≈1177 DMIPS

A Cortex-M4 manages about 1.25 DMIPS/MHz, so the M7 does about 70% more work per clock. The reason is its 6-stage superscalar pipeline, which can execute two instructions at once.

09

DSP instructions

digital signal processing
  • MAC (multiply-accumulate): sum += a * b in one instruction, the core operation of a filter.
  • SIMD (single instruction, multiple data): two 16-bit or four 8-bit values processed at once.
  • Saturating math: on overflow, the value stays at the maximum instead of wrapping to a negative number. Useful in audio and control.

ST's CMSIS-DSP library uses these for filters, FFTs and control loops.

Check yourself

tap to reveal
Who designed the Cortex-M7, and who designed the UART on your chip?

Arm designed the core. ST designed the UART and every other peripheral around it.

Why does the H735 need a cache to run at 550 MHz?

Flash is much slower than the core. Without a cache the CPU would stall for several wait states on every read; a cache hit returns data with 0 wait states.

Why can the MP257's A35 run Linux but the H735 can't?

Linux needs an MMU for virtual memory. The A35 has one; the M7 only has an MPU.

At 550 MHz, how long is one clock cycle?

1 / 550 000 000 s ≈ 1.8 ns.
